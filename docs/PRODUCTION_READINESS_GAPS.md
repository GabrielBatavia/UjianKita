# Production Readiness Gaps & Go / No-Go Checklist

While UjianKita's application logic, SQL migrations (`000001`–`000010`), live PostgreSQL RLS/RPC guarantees, authenticated Chromium/Pixel 7 E2E workflows, logical backup/restore parity, and 100-concurrent-student local HTTP+DB load tests have all been verified locally, **the platform must NOT be declared ready for official unsupervised school exams until the external/infrastructure gaps below are closed.**

---

## 1. Remaining Infrastructure, Scaling & Security Gaps

| Priority | Gap | Impact & Current State | Required Action Before Official Rollout |
|---|---|---|---|
| **Critical (Go/No-Go)** | **Cloud Supabase & Vercel Provisioning Postponed** | All Phase 5 tests ran against local Docker Supabase (`127.0.0.1`) and local `next start`. Cloud connection pooling, TLS/HSTS certificates, managed PITR backups, and regional network latency have not been measured. | Provision cloud Supabase Pro + commercial hosting (Vercel Pro or dedicated Node container host), configure production env secrets, run `supabase db push`, and re-benchmark p95 latency on staging. |
| **Critical (Go/No-Go)** | **Cohort Login IP Throttling Behind School Wi-Fi NAT (`auth:login:ip`)** | `src/app/api/auth/login/route.ts` enforces `enforceApiRateLimit(request, "auth:login:ip", 15, 5 * 60_000)` in addition to per-email throttling (`8` per `5` min). In a classroom where 30–100 students log in simultaneously behind one school Wi-Fi public IP, logins beyond #15 within 5 minutes receive HTTP `429`. | Pre-authenticate students >5 minutes before exam start (staggered login) OR refactor `auth:login:ip` using failed-login-only IP counters / higher NAT-aware IP allowance alongside per-email limits. |
| **High** | **In-Memory Rate Limiter Across Multi-Instance Serverless Workers** | `src/lib/rate-limit.ts` (`enforceApiRateLimit`, `enforceActorRateLimit`) uses per-process JavaScript memory maps. Across multiple serverless lambda instances on Vercel, rate-limit budgets do not share global state and reset on cold starts. | Replace or back `src/lib/rate-limit.ts` with a shared distributed store (e.g., Upstash Redis or PostgreSQL token bucket) before horizontal autoscaling. |
| **High** | **Physical Android ExamBro & iOS Safe Exam Browser Hardware Testing** | `ExamBro` SVG QR payloads and SEB `ConfigKey`/`RequestHash` verification pass unit and mocked service tests, and responsive mobile checks use Playwright `Pixel 7` Chromium emulation (`mobile-android`). Real APK/IPA kiosk WebViews have never run an exam against live HTTPS staging. | Run a supervised pilot on actual student Android devices running `com.dekikurnia.exambro` and iOS/macOS devices running Safe Exam Browser (`sebs://`, `updateKeys` callback) before enabling `VERIFIED_SEB_REQUIRED`. |
| **Medium** | **Staff TOTP Multi-Factor Authentication (MFA)** | `admin`, `teacher`, `exam_coordinator`, and `proctor` accounts currently rely on email + password (`enable_signup = false`). | Enforce Supabase Auth TOTP MFA enrollment for school administrators and staff with sensitive grading/override/retention permissions. |
| **Medium** | **Supabase Realtime Multi-Client WebSocket Fan-Out Under Cloud Load** | `supabase_realtime_ujiankita` runs locally and table replication is configured in `000009`, but concurrent 100-student presence updates streaming simultaneously to multiple proctor browsers over WebSockets were not stress-tested in a multi-proctor cloud soak test. | Verify cloud Supabase Realtime connection quotas and `15s` polling fallback behavior during a multi-proctor staging dress rehearsal. |
| **Low / Host-Specific** | **Windows Host WebKit Playwright Dependency (`mobile-iphone`)** | Playwright `mobile-iphone` (`iPhone 13`, WebKit) crashes on this Windows workstation due to missing native Windows WebKit DLL dependencies (`exitCode=3221225501`). | Executed automatically on Linux/Ubuntu runners in `.github/workflows/ci.yml` (`npx playwright install --with-deps chromium webkit`). Confirm Ubuntu CI green on every PR. |
| **Low / Informational** | **`npm audit` Transitive Moderate Advisories (`9 moderate`)** | Reported `9 moderate` vulnerabilities (`0` critical/high/low): `uuid <11.1.1` (`GHSA-w5hq-g745-h8pq` inside `exceljs >=3.5.0`) and dev-only `minimatch` (`GHSA-g3hv-75wg-m249` inside `@typescript-eslint/*`). `uuid` vulnerability requires `v3/v5/v6(buf)` calls not used by UjianKita. | Monitor upstream `exceljs` releases and `@typescript-eslint` updates; run `npm audit fix` for dev packages on maintenance cadence. |
